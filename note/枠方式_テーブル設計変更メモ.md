# 枠方式への移行に伴う テーブル設計 変更依頼メモ

作成日：2026-07-10 ／ 対象：`schema.sql`（PostgreSQL DDL）・`DATABASE.md`
このメモは「上映スケジュールを枠方式に変更する」ための **DBスキーマ変更のお願い** です。
DDLは案です。命名・型・制約は既存 `schema.sql`（`t_` テーブル / `f_` カラム / `SERIAL` PK）に合わせています。気になる点は「要相談ポイント」に、遠慮なく変更・指摘してください。

---

## 1. 何を変えたいか（背景）

いまの `t_SCHEDULE` は「映画×スクリーン×日付×開始時刻」を **1本ずつ手入力** して並べる方式。
これを、**あらかじめ用意した固定の「枠（入れ物）」に映画を割り当てる方式** に変えたい。

- 例：1スクリーンに「3時間枠 ×3・4時間枠 ×1」を先に用意 → そこに映画を入れる
- **掃除時間（一律20分想定）込みで枠に収まる映画だけ入れられる**
  判定式：`映画の上映時間(f_duration) + 掃除時間 ≦ 枠の長さ(f_duration_min)`
- 枠の余り時間 = 「飽き枠（空き時間）」→ 従業員の分担に使える
- 障害（機材故障・雨漏り等）時は、**空いてる枠／予備枠へ振替**して上映継続 → 予約者へ通知

管理者画面のUIモック（動作イメージ）：`admin/schedule.html`
設計の文章版：`DATABASE.md` の「6. 重要な設計ルール › 枠方式」

## 2. 変更サマリ（4点）

| # | 対象 | 変更内容 |
|---|------|----------|
| A | `t_SCHEDULE` | カラム `f_slot_id`（FK→t_SLOT）を **追加** |
| B | `t_SLOT`（新規） | 上映枠マスタ。スクリーン×日付ごとの固定枠。通常枠/予備枠を持つ |
| C | `t_SCHEDULE_CHANGE_LOG`（新規） | 振替・時刻変更・スクリーン変更・中止の履歴 |
| D | `t_NOTIFICATION`（新規） | 振替等を予約者へ通知するためのテーブル |

> B/C/D は「あると振替・通知まで通せる」もの。**最低限やりたいのは A + B**（枠割り当て）です。
> C/D は展示デモの「振替→通知」を本番DBでやる場合に必要。優先度は相談で。

## 3. DDL案（そのまま schema.sql に追記できる形）

### A. t_SCHEDULE にカラム追加

```sql
ALTER TABLE t_SCHEDULE
    ADD COLUMN f_slot_id INTEGER REFERENCES t_SLOT (f_slot_id);

CREATE INDEX idx_schedule_slot_id ON t_SCHEDULE (f_slot_id);
```

- `f_slot_id` は割り当て先の枠。枠運用では **開始時刻を手入力せず** `t_SLOT.f_start_time` からコピーする想定。
- 既存の `f_start_time` はそのまま残す（枠運用への移行期の互換 / 表示用）。
- ※ `t_SLOT` を先に作る必要があるため、schema.sql 上では **t_SLOT を t_SCHEDULE より前** に置くか、この ALTER を最後に回してください。

### B. t_SLOT（上映枠マスタ）※新規

```sql
CREATE TABLE t_SLOT (
    f_slot_id       SERIAL      PRIMARY KEY,
    f_screen_id     INTEGER     NOT NULL REFERENCES t_SCREEN (f_screen_id),
    f_show_date     DATE        NOT NULL,
    f_slot_order    SMALLINT    NOT NULL,             -- 同一スクリーン・同一日での並び順（1,2,3…）
    f_start_time    TIME        NOT NULL,             -- 枠の開始時刻
    f_duration_min  SMALLINT    NOT NULL,             -- 枠の長さ（分）180=3時間 / 240=4時間 など
    f_slot_type     SMALLINT    NOT NULL DEFAULT 0    -- 0:通常枠 / 1:予備枠（振替専用・通常予約を入れない）
        CHECK (f_slot_type IN (0, 1)),

    CONSTRAINT uq_slot UNIQUE (f_screen_id, f_show_date, f_slot_order)
);

CREATE INDEX idx_slot_screen_date ON t_SLOT (f_screen_id, f_show_date);
```

### C. t_SCHEDULE_CHANGE_LOG（振替履歴）※新規

```sql
CREATE TABLE t_SCHEDULE_CHANGE_LOG (
    f_change_id       SERIAL      PRIMARY KEY,
    f_schedule_id     INTEGER     NOT NULL REFERENCES t_SCHEDULE (f_schedule_id),
    f_change_type     SMALLINT    NOT NULL             -- 1:枠振替 / 2:時刻変更 / 3:スクリーン変更 / 4:中止
        CHECK (f_change_type IN (1, 2, 3, 4)),
    f_from_slot_id    INTEGER              REFERENCES t_SLOT (f_slot_id),
    f_to_slot_id      INTEGER              REFERENCES t_SLOT (f_slot_id),
    f_from_start_time TIME,
    f_to_start_time   TIME,
    f_reason          VARCHAR(255),                    -- 変更理由（機材故障・雨漏り 等）
    f_changed_by      INTEGER,                         -- 操作した管理者（管理者テーブル導入後にFK化）
    f_changed_at      TIMESTAMP   NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_change_log_schedule ON t_SCHEDULE_CHANGE_LOG (f_schedule_id);
```

### D. t_NOTIFICATION（通知）※新規

```sql
CREATE TABLE t_NOTIFICATION (
    f_notification_id SERIAL       PRIMARY KEY,
    f_member_id       INTEGER               REFERENCES t_MEMBER      (f_member_id),  -- ゲストはNULL
    f_reservation_id  INTEGER      NOT NULL REFERENCES t_RESERVATION (f_reservation_id),
    f_type            SMALLINT     NOT NULL             -- 1:枠振替 / 2:時刻変更 / 3:スクリーン変更 / 4:中止
        CHECK (f_type IN (1, 2, 3, 4)),
    f_message         VARCHAR(500) NOT NULL,
    f_is_read         SMALLINT     NOT NULL DEFAULT 0
        CHECK (f_is_read IN (0, 1)),
    f_created_at      TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_notification_member      ON t_NOTIFICATION (f_member_id);
CREATE INDEX idx_notification_reservation ON t_NOTIFICATION (f_reservation_id);
```

## 4. アプリ側でやること（DB側は不要・参考）

- 割り当て時に判定：`f_duration + 掃除時間 ≦ f_duration_min` を満たす枠のみ許可（超えたら弾く）
- 予約は `f_slot_type = 0`（通常枠）のみ対象。`f_slot_type = 1`（予備枠）は通常予約から除外
- 振替時：`t_SCHEDULE` の `f_slot_id`（必要なら `f_screen_id`/`f_start_time`）を更新 → `t_SCHEDULE_CHANGE_LOG` に記録 → 対象予約へ `t_NOTIFICATION` を生成
- 座席は枠単位で移せるので、振替時は移動先枠の `t_SEAT_STOCK` を初期化して割り当て直す

## 5. 要相談ポイント（ここを決めてほしい／直してほしい）

1. **掃除時間の持ち方**（どちらか）
   - A案：全映画で一律の定数（例20分）。DBには持たず、アプリ側の判定で使う（今のUIモックはこれ）
   - B案：枠の長さ `f_duration_min` に掃除込みで設定してしまう（掃除時間は明示的に持たない）
   - C案：スクリーンや映画ごとに掃除時間を変えたい場合 → `t_SCREEN` か `t_MOVIE` に `f_clean_min` を追加
   → 初期実装は **A案（一律20分）** を想定。問題なければA、変えたければ指定ください

2. **枠構成（3時間×3・4時間×1 など）** は
   - スクリーン×日付ごとに毎回 `t_SLOT` を作る想定（＝日によって枠構成を変えられる）で問題ないか
   - もし「毎日同じ枠を使い回す」なら、日付を持たない「枠テンプレート」テーブルにして日次で展開する案もあり（相談）

3. **予備枠の扱い**：`f_slot_type=1` を「予備枠」として1テーブルで表現しています。別テーブルに分けたい等あれば

4. **通知の宛先**：ゲスト予約（`f_member_id=NULL`）の連絡先をどう持つか。
   `t_RESERVATION` にゲスト用のメール/電話カラムが必要かも（現状なし）→ 通知を本番でやるなら要検討

5. **f_changed_by（操作管理者）**：管理者テーブルがまだ無いので今は INTEGER のみ。管理者テーブルを作るならFK化したい
